# Data Processing Agreement (DPA)

_Purpose: bind a Data Processor to handle personal data only on the Fiduciary's documented instructions and under contract. DPDP mapping: S.8(2) — a Fiduciary may engage a processor only under a valid contract. Source: https://www.dpdpa.com/templates/dataprocessingtemplate.html. Paraphrased structure. Last verified: 2026-06-15._

**When required**
Whenever a Data Fiduciary engages a Data Processor (cloud host, analytics, payment, SaaS sub-processor) to process personal data on its behalf. S.8(2) makes the contract a precondition for such engagement; the Fiduciary remains liable for compliance.

**Required clauses checklist** (paraphrased)
- Definitions (personal data, processing, sub-processor, controller/processor roles).
- Scope and purpose: permitted processing, data categories, duration.
- Processor obligations: process only on documented instructions; confidentiality bindings for personnel; reasonable security safeguards.
- Controller (Fiduciary) obligations: lawful instructions, audit/inspection rights.
- Sub-processor controls: prior approval, flow-down of equivalent obligations.
- Breach reporting from processor to Fiduciary within a defined (short) timeframe.
- Assistance with Data Principal rights requests and with DPIAs/audits.
- Cross-border transfer handling consistent with S.16.
- Indemnity and liability allocation.
- Term, termination, and return/secure-deletion of data on exit.
- Governing law (India) and dispute resolution.

**Audit signals**
- A signed DPA on file for each processor handling personal data.
- A maintained sub-processor list with approval status.
- Contractual breach-notification SLA matching the Fiduciary's own Rule 7 obligations.
- Evidence of vendor security commitments (encryption, access control) and audit rights.
- Data-deletion-on-termination clause, and proof it's exercised when vendors are offboarded.
